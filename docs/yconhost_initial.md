yconhost - это приложение для управления консолями на локальном хосте.
Стек: nodejs, typescript, react + ariakit, redux toolkit (при необходимости), также выбери подходящую библиотеку для отображения и взаимодействия с терминалами.

# Дополнительные требования

## Архитектура консоли

- Основным источником истины для каждой консоли является реальная Windows Console (`conhost.exe`), создаваемая вместе с процессом.
- yconhost не должен заменять или эмулировать `conhost.exe`, а должен выступать proxy/supervisor между пользователем и стандартной консолью Windows.
- Vanilla console должна существовать всегда, даже если она скрыта.

## Режимы ввода

- Должно существовать два режима работы:
    - `managed mode` — ввод идет через Web UI
    - `manual mode` — пользователь взаимодействует напрямую с vanilla console
- Во время `manual mode` UI должен переходить в read-only режим во избежание гонок ввода.

## Работа с процессами

- Все операции restart/kill должны работать со всей process tree, а не только с root PID.
- После restart/crash самого yconhost должна существовать возможность повторного re-attach к уже существующим процессам и их vanilla console.

## Логи и история

- История вывода консоли должна сохраняться между рестартами yconhost.
- Должна существовать настройка:
    - максимального объема логов
    - ротации логов
    - ограничения памяти под scrollback buffer

## Обработка ввода

- Ввод должен корректно поддерживать:
    - Ctrl+C
    - Ctrl+Break
    - paste
    - unicode
    - arrows/home/end/pageup/pagedown
    - tab
    - multiline input

## Обработка вывода

- Matchers/regex должны работать:
    - как по plain text
    - так и по ANSI colored output
- Должна существовать возможность отключения ANSI parser для отдельных процессов.

## Web UI / API

- Для live output необходимо использовать websocket или SSE streaming.
- Polling-only режим недостаточен.
- Для отображения терминала использовать `xterm.js`.
- xterm.js не должен модифицировать пользовательский ввод, удалять символы, блокировать вставку или выполнять "безопасную" нормализацию текста.

## Надежность

- При зависании UI или frontend пользователь всегда должен иметь возможность открыть vanilla console и продолжить работу напрямую через стандартный `conhost.exe`.
- yconhost не должен ломать стандартное поведение Windows Console.
# Основные требования
# Процессы
- Открыть/создать/Закрыть отдельную консоль
- Отобразить/Скрыть стандартное консольное окно
- Открыть/создать консоли пакетно - по файлу mywins.json из проекта (см пример файла)
- Перезапуск консоли в рамках проекта
- HTTP и HTTP MCP возможность
	- -Прочитать список консолей
		- -- Как по одному проекту
		- -- Так и все
	- - Прочитать последние несколько строк консоли
	- - Или прочитать весь вывод консоли
	- - Возможность выполнить в консоли любой текст
	- - Возможность перезапустить консоль
	- - Возможность отправить Ctrl+C в консоль и прочие особые команды
- Отслеживание ответов. Что это значит:
	- По мере ответа консольного приложения, ответы данного приложения должны конкатенироваться и затем их окончание ~1000 символов (настраиваемо через settings.json5) должны прогоняться через специальную функцию отслеживания.
	- Эта функция будет как общая, так и кастомизируемая под процесс
	- Цель существования данной функции - определение статуса процесса и количества ошибок в нем. По умолчанию считаем ошибкой любой красный или бордовый текст (стандартные цвета), а также строки включающие "error" или "errors" в любом регистре. При этом error должен быть словом, слева от него не должно быть "no" (тем самым мы исключаем "no errors"), а справа от него не должно быть 0 (тем самым исключаем "errors 0 - successful"). 

# Web UI
- Аутентификация/пользователи не требуется (т.к. на один хост всего один yconhost)
- Слева UI должен отображать список проектов + Default - если есть проекты запущенные без консоли, каждый из них можно открыть и увидеть название консолей с бэджами отображающими новых количество ошибок (с момента последнего просмотра), а также статус - работает (часики) или доступна для ввода (">").
- UI должен предоставлять возможность открыть ванильную консоль или скрыть ее. Также он должен позволять просмотреть терминал консоли - справа при выборе консоли слева
