# Закреплённый текст консоли

В настройках записи консоли поле `pinned_text` принимает многострочный текст
(до 65536 символов). Непустой текст отображается компактной панелью в начале
правой прокручиваемой области, перед карточками и терминалом. Пустое поле
полностью скрывает панель. Изменение только текста не перезапускает процесс
и не выставляет `pendingRestart`.

## Хранение

- Ручные папки: определение консоли в `consoles.json`.
- `my_wins`: свойство `pinned_text` записи в `wins` исходного JSON-файла.
- Scripted: скрипт возвращает `pinned_text` в элементе `list`, объявляет поле
  через `defineFields` и сохраняет его своим обработчиком `update`/`create`.

Для Codex/Claude текст хранится внутри соответствующего H1-раздела файла
`Codex contexts.md`, отдельно от команды запуска:

````markdown
```pinned_text
Work dir: "{{work_dir}}"
Project dir: "{{project_dir}}"
Session ID: {{session_id}}
```
````

Это также значение по умолчанию для новых записей и разделов без блока.
Явно пустой блок отключает панель. При сохранении заметок с тройными
обратными кавычками ограничитель автоматически удлиняется; заголовки и
команды внутри заметки не участвуют в разборе списка консолей.
Повторные или незакрытые блоки дают ошибку источника, сохраняя прежний список.

Для добавления отсутствующих блоков в существующий MD:

```powershell
node scripts/migrate-codex-pinned-text.mjs "D:\b\InfoVault\Codex contexts.md"
node scripts/migrate-codex-pinned-text.mjs "D:\b\InfoVault\Codex contexts.md" --write
```

Без `--write` выполняется только проверка. Запись сохраняет резервную копию
в `data/source-backups`, проверяет неизменность команд, каталогов, имён,
session ID и цветов; существующие блоки не перезаписываются.

## Подстановки

Scripted-папка может экспортировать `getVariables(context, entry)`. Ядро
передаёт поля `values` записи и её `key`, `name`, `cwd`, `command`.
Функция возвращает словарь максимум из 64 строковых значений с именами
в формате идентификаторов JavaScript. Она вызывается при перечитывании
списка для записей с подстановками. Ошибка функции сохраняет последний
успешный список и отображается как ошибка источника папки.

Codex/Claude возвращает:

- `work_dir`: рабочий каталог консоли (`cwd`).
- `project_dir`: каталог последнего `cd /d` в команде; без `cd` равен `work_dir`.
- `agents_dir`: совместимый псевдоним `project_dir`, не подкаталог `agents`.
- `session_id`: идентификатор возобновляемой сессии; пустая строка для новой.

У ручных и `my_wins` записей доступен `work_dir` без скрипта. Неизвестные
подстановки остаются текстом. Подстановка однопроходная: результат не
интерпретируется повторно. Ни JavaScript, ни HTML из текста не исполняются.

## Ссылки

Абсолютные Windows-пути (`D:\folder\file`, `D:/folder/file`, UNC) подсвечиваются;
нажатие копирует путь без кавычек в буфер обмена. Для путей с пробелами
используются двойные кавычки или обратные кавычки. Подстановки по умолчанию
уже заключены в кавычки. Копирование не открывает и не запускает файл.
При недоступном буфере панель показывает ошибку; текст можно выделить вручную.
HTTP(S)-адреса открываются в новой вкладке. Markdown и HTML отображаются
как обычный текст, без дополнительного форматирования.

## Проверка и Внедрение

Проверка проводится на отдельном порту `4021` и dataDir
`data/folder-verification`, без изменения продуктивного `dist` и без
перезапуска рабочих консолей. Для применения серверной части на `4011`
нужен отдельный согласованный перезапуск через PM2.
