# PM2: дубли после входа в Windows, 2026-11-12

## Причина

Одновременно включены три задания `PM2Resurrect`, `yconhost-pm2-resurrect`,
`codex-backup-pm2-resurrect` и запись `HKCU/.../Run/PM2` от pm2-windows-startup.
Они восстанавливали один общий `C:\Users\Administrator\.pm2\dump.pm2`.
Задание codex-backup использовало проектный PM2 7.0.1, другие — глобальный PM2.
Обнаружены два демона с одним PM2_HOME. Параллельные resurrect успевали
прочитать ещё неполный список и повторно восстановить одни и те же приложения.
В журнале — непрерывные рестарты лишних HTTP-серверов и terminal host из-за
занятых 4011/pipe; посторонний HTTP-процесс успевал обращаться к общим данным
до отказа listen. В UI дополнительно появлялась ошибка записи consoles.json.

Ошибка `Duplicate folder entry name "yconhost"` приходила из группы PM2,
а не из Markdown codexes. Реальные повторные процессы были отдельной
эксплуатационной проблемой; отображать реальные одноимённые процессы нормально.

## Разовое исправление машины

- Резервные копии dump, XML заданий и значения Run:
  `data/deploy-backups/pm2-duplicates-20261112-211000` (не коммитятся).
- Отключены `yconhost-pm2-resurrect` и `codex-backup-pm2-resurrect`.
  Последнее было Running; его выполнение остановлено.
- Удалена только запись `Run/PM2`, остальные записи автозапуска не менялись.
- Единственное включённое задание — `PM2Resurrect`, с явно заданным глобальным
  CLI и Node, одинаковым PM2_HOME и скрытым окном PowerShell.
- Удалены PM2-записи 2, 3, 7, 8, 9, 11, 12, 13. Оставлены младшие рабочие
  экземпляры: yconhost 1, Garden 4, backup 5, Chrome MCP 6, terminal host 10;
  модуль pm2-logrotate 0 сохранён. Младшие Garden 2 и terminal host 9 падали,
  поэтому работающие 4 и 10 не перезапускались ради перенумерации.
- Второй демон проектного PM2 остановлен после проверки отсутствия дочерних
  процессов. pm2.pid исправлен на PID оставшегося демона.
- Сохранены очищенные dump и backup. Автоматического исправления/удаления
  PM2-записей в yconhost нет, это только разовая административная операция.

Не добавлять отдельные resurrect для новых проектов: один Windows-пользователь
и один PM2_HOME должны иметь один общий механизм восстановления. Не смешивать
версии PM2 на одном домашнем каталоге. Восстановление проверяется повторным
запуском единственного задания без reboot и сравнением списка/PID сервисов.

## Проверка

Единственное задание вручную запущено дважды: оба завершения с кодом 0,
число записей, их ID и PID остались прежними. Проверены основной dump и bak:
пять сервисов, повторяющихся имён нет; модуль pm2-logrotate сохраняется отдельно.
Оставшийся демон — 15548. Все пять сервисов online, лишние restart-loop исчезли.

После исправления политики имён и шаблона Codex обновлён только HTTP-процесс
PM2 №1. Terminal host 22500 и одна работающая пользовательская консоль сохранены;
`/api/health` успешен, в `/api/projects` нет ошибок источников. Typecheck/build
и 137 тестов (21 файл) прошли. В UI проверены длинные ошибки в compact/dark
и touch/light на 390 px: без пересечений и горизонтального переполнения.
UI-сбой для снимков подставлялся только в тестовом браузере, серверные данные
для воспроизведения ошибки не изменялись.
